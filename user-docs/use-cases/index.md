# Use Cases

RecordKit is useful when the shape of the record should belong to the person collecting it rather than the application developer.

## Health, symptoms, and activities

Combine dates, times, scales, booleans, selections, durations, and notes to record symptoms and the context around them. A user can adapt the template as their own tracking needs become clearer.

## Journal and state tracking

Use sections to combine structured values with free text. This can preserve the readability of a journal while making recurring details consistent enough to compare later.

## Food logging

Build a template around the details that matter to you—ingredients, time, quantities, reactions, context, or notes—without adopting a fixed diet application's schema.

## Personal research and reference records

Use text, dates, selections, and nested sections to keep consistent human-readable notes about sources, events, local history, infrastructure, or another domain.

These are examples rather than built-in modes. RecordKit's value comes from configuring the model rather than choosing among fixed trackers.
